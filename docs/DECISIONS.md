### 2026-09-15 — decisions made by the build workstreams (curated from their reports)

**Tasks & Today.** No `/tasks/[id]` route — task detail is a sheet. Reschedule quick options: Tomorrow / This weekend (coming Saturday) / Next week (next Monday) / Clear / Pick. Today's groups are exclusive (overdue beats rolling-over). Recurrence spawns anchor to max(own date, today) so overdue recurring tasks don't respawn in the past; an unparseable RRULE never blocks completion. Mirrored projects (with `notion_url`) are read-only like mirror tasks. Areas can't carry target dates (§4.1 "areas are ongoing").

**Quick-add.** `!med`/`!medium`/`!none` accepted; `#domain/project` matches slug-or-name prefix, unresolved halves degrade gracefully; `@token` matches any name word (`@niesner` → Bernhard Niesner); date phrases up to 4 trailing words, never article-led ("Plan the week" keeps its title), never allowed to empty the title; `3pm` → due today 15:00.

**Routines & notifications.** Logging a routine cancels both the reminder and the missed nudge; deactivating/deleting a routine cancels its pushes; time-of-day notifications are enqueued at the exact local target time so the dedupe index makes re-runs no-ops; push copy is split title/body for iOS; zero-device delivery marks the row `failed`, not `sent`; the 21:00 streak line is present-tense ("Gym streak at 12, not logged today"); nudge payloads carry their local `date` so a post-midnight fire logs the right day. Per-kind toggles (`notification_kind_toggles` settings key) are enforced in the tick; missing key = on.

**Capture.** Typed captures skip the cleanup LLM pass (Joshua authored them). Captures never auto-create projects (people yes, at high confidence). Model-returned ids are validated against real tables; a retry deletes its own prior capture-origin tasks first so failures don't duplicate.

**Integrations.** `source_items.external_id` is namespaced per account (`gmail:{account}:{thread}` etc.) — the same thread on two accounts is deliberately two archive rows. `content_hash` covers title+text only, so raw payload churn never re-triggers extraction. App-created calendar events are not archived (our own writes must not feed the sweep); cancelled events keep their archive row. Gmail: 25 threads/run, newsletter threads skipped only when every message matches, history cursor advances only after a full batch. Block-time slotting: due time if set, else first free 60-min gap (freebusy) today 08:00–18:00, else tomorrow morning. Dropped task = calendar block removed; done = " ✓" appended, never deleted. OAuth state is HMAC-signed with a nonce cookie. Removing an account keeps the archive (FK nulls `account_id`). Google consent screen must go to "In production" — log here when done.

**Queue/people/review.** Kind labels map `task`→Commitment, spec has no separate Request kind. Undated follow-ups default to +3 days. Review "Delegate" converts the task to `owner=them` rather than duplicating it. Person "Park" clears the follow-up cadence. The scorecard freezes onto the review row when leaving step 1 so the coach reads the same numbers. `person-matching.md` prompt dropped — matching is deterministic by email. Coach `pattern_flags` are not persisted (no column).

### 2026-09-15 — security-audit hardening

An adversarial security pass reviewed the whole app. Fixes applied: pg_cron's `private.call_job` execute revoked from PUBLIC; the notification dedupe index scoped per user; `job_runs`/`ai_calls.user_id` made NOT NULL with jobs failing loudly when the owner can't be resolved; owner resolution pinned via `OWNER_USER_ID` env (falling back to the *oldest* auth user, never the newest) plus a middleware gate that signs out any other user; the service worker no longer caches `/api/*` (the export zip and transcripts were landing in CacheStorage) and runtime caches are cleared on reaching /login; CSP moved to middleware with a per-request script nonce replacing `'unsafe-inline'`; HSTS added. **Operational requirement: Joshua must disable public email signups in Supabase Auth settings and set `OWNER_USER_ID` in Vercel.** Remaining accepted risk, logged deliberately: extracted email/meeting text is untrusted LLM input — the accept/dismiss review queue is the primary mitigation (per the spec's own design); prompt-level hardening and accept-side id validation are applied as defence in depth.

- **2026-09-15 — security fix round notes.** Granola OAuth now carries signed CSRF state like Google. OAuth state signatures are HKDF-derived from `TOKEN_ENCRYPTION_KEY` (label `lifeos-oauth-state`) — any OAuth connect in flight during a deploy of this change fails once and needs a re-click. Capture audio now lives under `captures/<user_id>/…`; any audio previously at the bucket root stays transcribable by jobs but is no longer client-downloadable. `GranolaSection` still reads token presence server-side only (never serialized to the client) — acceptable; all client components now receive a `ConnectedAccountSummary` DTO without token or sync-state fields.

- **2026-09-15 — QA polish round.** `isDueNow` compares modulo the 1440-minute day, so a target in the last window before midnight (23:50 on 15-minute ticks) fires on the 00:00 tick instead of being skipped; covered by `tests/time.test.ts`. Morning planning runs at `min(morning_brief_time, 06:30)` so a brief set earlier than 06:30 still has a plan to read. Undoing a routine log re-schedules that day's cancelled reminder/missed pushes, but only the ones still in the future — a push whose moment has passed stays cancelled. During quiet hours `notifications-tick` queries only the routine kinds (the ones quiet hours can act on) and counts the rest as held, so held rows can no longer fill the 25-row batch and starve the routine rows. Routine calendar events are patched and deleted on the account they were created on (looked up from `calendar_events`), not on whichever account `pickWritableAccount` would choose today; only a fresh create picks an account. Timezone is now settable in Settings → Appearance (validated server-side against the platform's zone table). Captures that fail on a network error are parked in IndexedDB (`components/capture/offline-queue.ts`, memory fallback on quota) and replayed on `online` and on mount; a capture the server rejects on its merits is dropped with a message rather than retried forever. Decided by: Claude Code.

- **2026-09-16 — Smart add reuses the capture pipeline rather than a second parser.** Joshua's first-use feedback: a sentence with several to-dos in it ("I want to make chicken katsu today with priority very high and before 12 noon") became one literal task, because quick-add is the deterministic token parser (`#domain !priority ~date`). Rather than teach that parser English, the quick-add field and the command palette now offer a second action, **Smart add**, which POSTs the raw text to `/api/capture` with source `desktop_text` — exactly the path the capture screen uses — and polls the capture row until it is `done`/`failed`, then toasts the real counts ("Added 2 tasks and 1 note"). Plain **Add** stays the default on Enter and on ⌘⏎: it is instant, offline-safe and predictable, and Joshua should not pay an LLM round-trip for "buy milk". Shared logic lives in `components/capture/use-smart-add.ts`; there is no parallel filing pipeline. Smart add always reports `desktop_text` as the source (per the build instruction), so a phone Smart add is archived as a desktop capture — cosmetic, only affects the source label in the archive. Decided by: Joshua (the behaviour), Claude Code (reuse over a second parser).

- **2026-09-16 — `duration_minutes` on filed tasks, carried in the body and in `captures.result`.** The file-capture schema now asks for a realistic estimate of active time on `task`/`reminder` items, set only where an activity has a natural length (cooking, workout, errand, call) and left null for open-ended work. There is no `tasks.duration_minutes` column and this round touched no migrations, so the estimate is appended to `body_md` as a final `Estimated: N min` line and stashed on the `captures.result` item. That is enough for the Google calendar block length to read it when calendar write is wired up; nothing writes to a calendar now. Values outside 1–1440 minutes are dropped. Decided by: Claude Code.

- **2026-09-16 — The transcript cleanup pass is skipped for short captures.** Cleanup was already skipped for typed captures (Joshua's own words). It is now also skipped when a voice transcript is under 240 characters: it is a whole extra LLM round-trip, the file-capture prompt already tolerates filler and false starts, and on a one-or-two-sentence clip it bought nothing but latency. Long rambles are still cleaned first. Decided by: Claude Code, in response to "listening back and filing takes too long".

- **2026-09-16 — Capture progress is a three-step strip, not a spinner.** Joshua asked for "an animation so we know something is happening". The capture screen shows Transcribing → Filing → Done driven by the polled `captures.status`, the active step marked with a pulsing accent dot (opacity only, dropped under `prefers-reduced-motion`), and the elapsed seconds in mono. Polling starts at 1s and backs off to 2.5s after ten seconds. After 45 seconds with no status change it says "Still working. You can leave — it finishes in the background." rather than presenting as stuck — which is true: the `process-captures` job finishes it whether or not the screen is open. Decided by: Claude Code.

- **2026-09-16 — The default Add is the smart one.** Joshua: "make it automatic so that the add button is smart." Enter and the accent Add button (tasks quick-add, ⌘K palette) now send the sentence through the capture pipeline — splitting several to-dos, reading dates, priorities, people, and estimating duration. The instant deterministic token parse remains as the secondary path: "As typed" ghost button and ⌘⏎ in the quick-add, an "Add exactly as typed" row and header button in the palette. Rationale: the deterministic parse was the default only because it is instant, but Joshua's first real use showed he types plain English, not token syntax; the fast path is one keystroke away for anyone who wants it. Decided by: Joshua.

- **2026-09-16 — Recording happens in place, not on a page.** Joshua: "I could record while I'm on the Today page, not going to a different page." The tab-bar mic (and a palette command) now opens a bottom sheet over whatever screen is open — waveform, elapsed time, stop/discard — and files through the same capture pipeline, reporting through a toast while he keeps working. The full capture screen stays (More → Capture screen) for text mode, history and retries. One recorder implementation (`use-recorder`) backs both surfaces. Audio captures are also now processed in the same server invocation via Next `after()` instead of a fire-and-forget HTTP kick, so transcription starts the moment the upload lands; the every-minute cron stays as the safety net. Decided by: Joshua (in-place recording), Claude Code (after(), shared hook).
- **2026-09-16 — Motion: entrances and tap feedback, still no bounce.** Joshua: "the website is very stiff." Added 150–240ms ease-out entrances (sheets rise, overlays fade, palette pops, each page settles in via a route template) and a scale dip on press for buttons and the task checkbox. Everything is an animation, so the existing prefers-reduced-motion kill switch covers it all. Nothing springs, nothing bounces — DESIGN_BRIEF §3 still holds. Decided by: Joshua.
- **2026-09-16 — Settings grouped, jobs named in plain language, Sync now buttons.** Joshua: "make sure that the system page looks well made." The page now reads as four Fraunces-titled groups (Connections / Notifications / System / Data & appearance), job rows carry plain names ("Gmail & Calendar sync", not `sync-google`), and safe jobs plus the Notion and Granola rows get a "Sync now"/"Run now" button — a signed-in server action that relays to the same secret-protected job route the scheduler uses, so a new connection can be tested immediately instead of waiting for the next cron tick. Decided by: Joshua (look), Claude Code (run-now mechanism).

- **2026-09-17 — Task deadlines push, like routines do.** Joshua: "no notifications when it's the due date for the task." New notification kind `task_due`: a task with a due time pushes 30 minutes before it; a day task pushes at 10:00 the day before. Enqueued by schedule-day (pre-scheduled at the exact minute, deduped per task+deadline), sent by notifications-tick, which re-checks at send time that the task is still open with the same deadline — a completed or rescheduled task never buzzes. Respects quiet hours and gets its own Settings toggle ("Task deadlines"). Requires one constraint change in the live DB (`notifications_kind_check` gains 'task_due'); the block is at the end of scripts/deploy-database.sql. Decided by: Joshua (feature), Claude Code (10:00 day-before default — adjustable later).
- **2026-09-17 — Names link to People automatically.** Joshua: "if I say Lucas and there's a person named Lucas, connect it; if not, suggest adding him." Two layers: the filing prompt now carries explicit matching rules (case-insensitive; a bare first name links when exactly one known person has it; ambiguity or an unknown name becomes a needs_clarification question, never an invented person), and a deterministic server-side net (`lib/domain/person-match.ts`, whole-word, accent-insensitive, unique-match-only) fills any person_id the model missed. new_person stays reserved for person_update facts. Decided by: Joshua.
- **2026-09-17 — Frosted chrome, skeletons, and a lazy palette.** Joshua asked about Liquid Glass. Verdict: the warm-paper canvas stays, but the floating chrome (tab bar, sheets, palette, filing pill) goes translucent with backdrop blur at ≥80% opacity, with solid paper as the automatic fallback where backdrop-filter is unsupported. Route changes paint an instant skeleton (app/(app)/loading.tsx, opacity pulse only, still under reduced-motion). The command palette (cmdk + chrono-node) is now dynamically imported so its parser no longer loads on every screen. Decided by: Joshua (feel), Claude Code (mechanics).
- **2026-09-17 — Reliability round from the platform survey.** An audit pass over mobile/desktop/connections produced fixes shipped together: offline captures now flush from any screen (shell-level flusher; they used to wait for a /capture visit) and smart add parks offline instead of failing; the PWA refreshes itself when reopened after >60s away (iOS keeps the DOM alive for days); all-day Google events are stored on the right local day (they sat at UTC midnight, i.e. the previous evening in New York); Notion/Granola sync cursors no longer advance past unfetched pages on a truncated run; Google "Reconnect" pre-selects the account being repaired (login_hint) so a multi-account browser can't re-consent the wrong identity; a successful sync clears a stale needs_reauth badge; and Anthropic prompt caching is enabled through OpenRouter on the stable system prefix (rules + context), which is most of the repeated extraction cost. Remaining survey items worth doing later are in the session log, headed by: undo for task complete and queue swipes, a pushsubscriptionchange handler in the service worker, per-thread incremental email extraction, and Granola transcript length guards. Decided by: Claude Code under the standing "if you see improvements, do it" instruction.
