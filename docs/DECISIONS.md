### 2026-09-15 — decisions made by the build workstreams (curated from their reports)

**Tasks & Today.** No `/tasks/[id]` route — task detail is a sheet. Reschedule quick options: Tomorrow / This weekend (coming Saturday) / Next week (next Monday) / Clear / Pick. Today's groups are exclusive (overdue beats rolling-over). Recurrence spawns anchor to max(own date, today) so overdue recurring tasks don't respawn in the past; an unparseable RRULE never blocks completion. Mirrored projects (with `notion_url`) are read-only like mirror tasks. Areas can't carry target dates (§4.1 "areas are ongoing").

**Quick-add.** `!med`/`!medium`/`!none` accepted; `#domain/project` matches slug-or-name prefix, unresolved halves degrade gracefully; `@token` matches any name word (`@niesner` → Bernhard Niesner); date phrases up to 4 trailing words, never article-led ("Plan the week" keeps its title), never allowed to empty the title; `3pm` → due today 15:00.

**Routines & notifications.** Logging a routine cancels both the reminder and the missed nudge; deactivating/deleting a routine cancels its pushes; time-of-day notifications are enqueued at the exact local target time so the dedupe index makes re-runs no-ops; push copy is split title/body for iOS; zero-device delivery marks the row `failed`, not `sent`; the 21:00 streak line is present-tense ("Gym streak at 12, not logged today"); nudge payloads carry their local `date` so a post-midnight fire logs the right day. Per-kind toggles (`notification_kind_toggles` settings key) are enforced in the tick; missing key = on.

**Capture.** Typed captures skip the cleanup LLM pass (Joshua authored them). Captures never auto-create projects (people yes, at high confidence). Model-returned ids are validated against real tables; a retry deletes its own prior capture-origin tasks first so failures don't duplicate.

**Integrations.** `source_items.external_id` is namespaced per account (`gmail:{account}:{thread}` etc.) — the same thread on two accounts is deliberately two archive rows. `content_hash` covers title+text only, so raw payload churn never re-triggers extraction. App-created calendar events are not archived (our own writes must not feed the sweep); cancelled events keep their archive row. Gmail: 25 threads/run, newsletter threads skipped only when every message matches, history cursor advances only after a full batch. Block-time slotting: due time if set, else first free 60-min gap (freebusy) today 08:00–18:00, else tomorrow morning. Dropped task = calendar block removed; done = " ✓" appended, never deleted. OAuth state is HMAC-signed with a nonce cookie. Removing an account keeps the archive (FK nulls `account_id`). Google consent screen must go to "In production" — log here when done.

**Queue/people/review.** Kind labels map `task`→Commitment, spec has no separate Request kind. Undated follow-ups default to +3 days. Review "Delegate" converts the task to `owner=them` rather than duplicating it. Person "Park" clears the follow-up cadence. The scorecard freezes onto the review row when leaving step 1 so the coach reads the same numbers. `person-matching.md` prompt dropped — matching is deterministic by email. Coach `pattern_flags` are not persisted (no column).

### 2026-09-15 — security-audit hardening

An adversarial security pass reviewed the whole app. Fixes applied: pg_cron's `private.call_job` execute revoked from PUBLIC; the notification dedupe index scoped per user; `job_runs`/`ai_calls.user_id` made NOT NULL with jobs failing loudly when the owner can't be resolved; owner resolution pinned via `OWNER_USER_ID` env (falling back to the *oldest* auth user, never the newest) plus a middleware gate that signs out any other user; the service worker no longer caches `/api/*` (the export zip and transcripts were landing in CacheStorage) and runtime caches are cleared on reaching /login; CSP moved to middleware with a per-request script nonce replacing `'unsafe-inline'`; HSTS added. **Operational requirement: Joshua must disable public email signups in Supabase Auth settings and set `OWNER_USER_ID` in Vercel.** Remaining accepted risk, logged deliberately: extracted email/meeting text is untrusted LLM input — the accept/dismiss review queue is the primary mitigation (per the spec's own design); prompt-level hardening and accept-side id validation are applied as defence in depth.

- **2026-09-15 — security fix round notes.** Granola OAuth now carries signed CSRF state like Google. OAuth state signatures are HKDF-derived from `TOKEN_ENCRYPTION_KEY` (label `lifeos-oauth-state`) — any OAuth connect in flight during a deploy of this change fails once and needs a re-click. Capture audio now lives under `captures/<user_id>/…`; any audio previously at the bucket root stays transcribable by jobs but is no longer client-downloadable. `GranolaSection` still reads token presence server-side only (never serialized to the client) — acceptable; all client components now receive a `ConnectedAccountSummary` DTO without token or sync-state fields.
